此套為局部代表卡，不代表全部命運與投資標的均已換圖。所有 PNG 為本專案現有 PlayCanvas 角色及新建程序道具直接渲染，未使用 ImageGen 或外部圖片；原有圖檔保持不動。

## 對應方式

| 畫面 | 檔案與精確對應 |
|---|---|
| 六職業卡 | `career-{founder,freelancer,engineer,doctor,sales,assistant}.png`，768×960 |
| 個人收入圖 | income-{careerId}.png 六職業本人；固定/浮動道具依官方初始收入池 |
| 固定收入 | `income-fixed.png`，適用工程師、醫生、公司助理的固定收入畫面 |
| 浮動收入 | `income-variable.png`，適用創業家、自由業者、公司業務的抽收入畫面 |
| 六投資類別入口 | `category-{stock,property,venture,metal,crypto,forex}.png`，512×512；是該類代表示意 |
| 特定投資標的 | `investment-IA001.png` 環保能源股；`IB001` 市區住宅公寓；`IC001` 路邊餐車創業；`ID001` 實體金條；`IE002` 小型區塊鏈項目；`IF001` 美元現鈔兌換 |
| 一般命運 | `fate-DA005.png`，參加理財工作坊 |
| 職業命運 | `fate-JC001.png`，工程師技術突破 |
| 小確幸 | `lucky-L001.png`，發票中獎 |

投資、收入及事件大圖為1024×768。資料來源、原始卡義、尺寸、SHA256 與每圖可存取描述均在 `manifest.json`。只對精確 ID 使用事件/標的專屬圖；其他卡保留既有內容，不可把餐車圖套給所有創業標的、把金條圖套給銀幣。類別入口可以使用 category 圖。

## 整合建議

- 用單一 `<img>` 顯示候選圖；若沿用 `.topic-art`，需移除舊 atlas 的背景尺寸/定位及疊加 SVG，避免雙圖重疊。
- 六職業使用 `object-fit:contain`，維持4:5完整比例；不要裁掉帽子、低馬尾或手持道具。人物與棋子共用同一模型。
- 事件圖使用4:3且 `object-fit:contain`；圖片本身背景米色，卡片圖框可採 `#f2ead8`。避免透明背景假設。
- 投資類別用1:1方形圖；特定標的用4:3圖。不要把方形入口圖拉伸成寬幅。
- 收入畫面優先依 current.career.id 選 income-{careerId}.png。六張基礎圖對應官方初始池；工程師、醫生、助理若 activeIncomePool 已變浮動，使用新增 income-engineer-variable.png、income-doctor-variable.png、income-assistant-variable.png。原 career.id 仍決定本人外觀。生成器的 career 和 kind 可獨立指定。
- 固定/浮動收入圖不含金額；正式金額、費用、利率、解鎖回合全部仍由既有資料與 UI 呈現。圖片不是規則來源。
- 角色出現在收入/事件圖僅為示意，避免將其當作限定該職業才適用的規則。
- 首批需由主代理在1280、390、430實際同畫面比較：標題、金額、效果、按鈕、倒數及人物焦點均不得被插圖擠壓。

## 重跑與驗證

於 browser-game 目錄、現有8836伺服器可用時：

```text
node qa-r32-card-assets.mjs
node qa-r32-card-assets-verify.mjs
```

生成器只寫本資料夾。驗證器確認 manifest 所列全部36張的尺寸、非背景像素覆蓋率、內容邊界留白，並產生 evidence contact sheet。`index.html` 為素材比較頁。實際瀏覽圖像仍不可省略；`manifest.passed` 只代表生成與模型來源未變，`qa.json` 是像素驗證，兩者均不等同實際遊戲布局或使用者驗收。

本批無需在玩家端增加3D渲染成本，使用 PNG 即可。程序道具的 mesh 數記於 manifest，僅供資產生成成本參考。
